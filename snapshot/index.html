Introduction

This plugin makes Grails enums translatable. Annotate an enum with @I18nEnum - or implement the I18nEnumTrait - and it implements Spring’s MessageSourceResolvable interface, so the enum constant can be handed straight to Grails' messageSource, to <g:message> or to anything else that resolves message codes.

The codes are derived from the enum’s package, class and constant name in a predictable way, and can be tuned per annotation or globally from the application configuration.

It was heavily inspired by this blog entry by Rob Fletcher.

A runnable example lives in examples/app1 in the source repository - it wires all three flavours (plain annotation, annotation with overrides, and the trait) into a small Grails application.

Usage

Installation

In your build.gradle add the plugin to your dependencies:

Grails 8.x

implementation 'org.grails.plugins:i18n-enums:8.0.0-SNAPSHOT'
The 8.x line requires Grails 8, which in turn requires Java 21 or later and Groovy 5. For Grails 7.x use the 7.0.x line of this plugin.

Grails 7.x

implementation 'org.grails.plugins:i18n-enums:7.0.1'
From version 7.0.0 the plugin lives at https://github.com/grails-plugins/i18n-enums.

Grails 6.x

implementation 'dk.glasius:i18n-enums:6.0.0'

Grails 5.x

implementation 'dk.glasius:i18n-enums:5.0.0'

Grails 4.x

There is no released version for Grails 4.x - try the Grails 3.x version.

Grails 3.x

compile 'org.grails.plugins:i18n-enums:2.0.2'

Basic usage

There are two ways to use the plugin.

Annotate the enum with @I18nEnum:

package test

import grails.plugins.i18nEnums.annotations.I18nEnum

@I18nEnum
enum MyEnum {
    ONE, Two, three
}

or implement the I18nEnumTrait on it:

package test

import grails.plugins.i18nEnums.traits.I18nEnumTrait

enum MyEnum implements I18nEnumTrait {
    ONE, Two, three
}

Both generate the following codes for each constant:

test.MyEnum.ONE.codes   == ['test.MyEnum.ONE',   'test.MyEnum.ONE',   'test.MyEnum.one']
test.MyEnum.Two.codes   == ['test.MyEnum.TWO',   'test.MyEnum.Two',   'test.MyEnum.two']
test.MyEnum.three.codes == ['test.MyEnum.THREE', 'test.MyEnum.three', 'test.MyEnum.three']

and the following default messages:

test.MyEnum.ONE.defaultMessage   == 'ONE'
test.MyEnum.Two.defaultMessage   == 'Two'
test.MyEnum.three.defaultMessage == 'three'

As you can see, the codes come in three variations - UPPER_CASE, UNCHANGED and LOWER_CASE - and the default message is simply the enum value.

Because the constants implement MessageSourceResolvable, they can be resolved directly:

messageSource.getMessage(MyEnum.ONE, locale)

and in a GSP:

<g:message message="${MyEnum.ONE}"/>

The difference between the two flavours is configurability: the trait can only be configured from the application configuration (see Configuration), while the annotation additionally supports fine-grained per-enum configuration (see Advanced usage).

Advanced usage

To get more control over how the codes and the default message are generated, add members to the annotation:

@I18nEnum(prefix = '', postfix = '', shortName = false, defaultNameCase = DefaultNameCase.UNCHANGED)

The values above are the defaults. Any member you set overrides the corresponding application configuration setting; anything you leave out falls back to it.

Prefix and postfix

prefix controls what is added before the package name. If you do not add a dot after the prefix, one is added for you.

postfix controls what is added after the enum constant. If you do not add a dot before the postfix, one is added for you.

package test

import grails.plugins.i18nEnums.annotations.I18nEnum

@I18nEnum(prefix = 'enum', postfix = 'label')
enum MyEnum {
    ONE, Two, three
}

generates:

test.MyEnum.ONE.codes   == ['enum.test.MyEnum.ONE.label',   'enum.test.MyEnum.ONE.label',   'enum.test.MyEnum.one.label']
test.MyEnum.Two.codes   == ['enum.test.MyEnum.TWO.label',   'enum.test.MyEnum.Two.label',   'enum.test.MyEnum.two.label']
test.MyEnum.three.codes == ['enum.test.MyEnum.THREE.label', 'enum.test.MyEnum.three.label', 'enum.test.MyEnum.three.label']

shortName

If you do not want the package name in the generated codes, set shortName = true:

package test

import grails.plugins.i18nEnums.annotations.I18nEnum

@I18nEnum(shortName = true)
enum MyEnum {
    ONE, Two, three
}

generates:

test.MyEnum.ONE.codes   == ['MyEnum.ONE',   'MyEnum.ONE',   'MyEnum.one']
test.MyEnum.Two.codes   == ['MyEnum.TWO',   'MyEnum.Two',   'MyEnum.two']
test.MyEnum.three.codes == ['MyEnum.THREE', 'MyEnum.three', 'MyEnum.three']

defaultNameCase

defaultNameCase controls the defaultMessage. It takes one of the values of grails.plugins.i18nEnums.DefaultNameCase:

UPPER_CASE, LOWER_CASE, CAPITALIZE, ALL_CAPS, UNCHANGED

where UNCHANGED is the default.

DefaultNameCase.CAPITALIZE:

package test

import grails.plugins.i18nEnums.DefaultNameCase
import grails.plugins.i18nEnums.annotations.I18nEnum

@I18nEnum(defaultNameCase = DefaultNameCase.CAPITALIZE)
enum MyEnum {
    ONE, Two, three
}

gives the default messages:

test.MyEnum.ONE.defaultMessage   == 'One'
test.MyEnum.Two.defaultMessage   == 'Two'
test.MyEnum.three.defaultMessage == 'Three'

DefaultNameCase.ALL_CAPS additionally splits the constant on underscores:

package test

import grails.plugins.i18nEnums.DefaultNameCase
import grails.plugins.i18nEnums.annotations.I18nEnum

@I18nEnum(defaultNameCase = DefaultNameCase.ALL_CAPS)
enum MyEnum {
    ONE, Two, three, Four_five
}

gives:

test.MyEnum.ONE.defaultMessage       == 'One'
test.MyEnum.Two.defaultMessage       == 'Two'
test.MyEnum.three.defaultMessage     == 'Three'
test.MyEnum.Four_five.defaultMessage == 'Four Five'

DefaultNameCase.LOWER_CASE:

package test

import grails.plugins.i18nEnums.DefaultNameCase
import grails.plugins.i18nEnums.annotations.I18nEnum

@I18nEnum(defaultNameCase = DefaultNameCase.LOWER_CASE)
enum MyEnum {
    ONE, Two, three
}

gives:

test.MyEnum.ONE.defaultMessage   == 'one'
test.MyEnum.Two.defaultMessage   == 'two'
test.MyEnum.three.defaultMessage == 'three'

Configuration

Application-wide defaults are set under grails.plugin.i18nEnum. This is the only way to configure code generation for enums that use the I18nEnumTrait; for annotated enums it provides the defaults that individual annotation members override.

In application.yml:

grails:
  plugin:
    i18nEnum:
      prefix: enum
      postfix: label
      shortName: true
      defaultNameCase: ALL_CAPS

or in application.groovy:

import grails.plugins.i18nEnums.DefaultNameCase

grails {
    plugin {
        i18nEnum {
            prefix = 'enum'
            postfix = 'label'
            shortName = true
            defaultNameCase = DefaultNameCase.ALL_CAPS
        }
    }
}

The setting names and their meanings are the same as the annotation members described in Advanced usage.

Release Notes

v8.0.0

Ported to Grails 8.x. Requires Java 21 or later.

Groovy 5’s TraitComposer no longer copies a trait’s private methods onto the implementing class. I18nEnumTrait therefore no longer carries the annotation config in an overridable method; @I18nEnum now bakes it into a static field on the enum, which the trait reads at runtime. Behaviour is unchanged - the codes, default messages and configuration precedence are exactly as before.
